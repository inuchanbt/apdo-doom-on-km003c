# APDO — DOOM on KM003C

[English](README.md) · [日本語](README.ja.md)

> 本プロジェクトは、EPR（Extended Pixel Range）規格に準拠し、高負荷な戦闘シーンでは AVS（Adjustable Violence System）によって暴力描写とフレームレートを100mHz単位で動的に最適化。最終的に APDO（Augmented Power DOOM Object）としてKM003Cの画面へ出力される――

*上記のEPR・AVS・APDOはUSB-PD用語にかけたジョークです。実装はネイティブDOOM移植で、実測性能は下表に記載しています。*

**POWER-Z KM003CでDOOMが動きました。** 正確には、省メモリ版DOOMエンジンでFreedoomのE1M1を実行します。PCはビルド・書き込み・検証に使い、ゲーム処理はKM003C本体のMCUで行います。

## 書き込みのリスク — 必ず先に確認

**実験用ファームウェアです。書き込みによって起動不能や工場データの喪失が発生し、
修理・買い直しが必要になる可能性があります。バックアップがあっても復旧は保証できません。**
誤った画像、更新中の切断・電源断、ハードウェアの差異、ソフトの不具合などで、通常起動やUSB接続ができなくなる場合があります。

- 検証したのは **元ファーム2.0.7のKM003C HW2.3・1台のみ** です。
  すべてのHW2.3個体や、他のリビジョンでの動作を保証するものではありません。
- 初回のカスタムアプリ書き込み前に、**自分の個体の** 純正／DFUバックアップを検証し、
  純正復旧パッケージと別の保存先へのコピーを用意してください。ゲームデータを書き込む前には、
  元の **外部NOR全4MiBのバックアップ** も取得・検証します。
  [初回バックアップ手順（英語）](docs/FIRST-BACKUP.md)の順序を守り、他個体のローダー・校正値・復旧データで代用しないでください。
- ゲームデータは元の **外部NOR先頭3MiBを上書き** します。純正アプリだけを書き戻しても元には戻りません。
  元のNORデータと純正アプリを、[復旧手順（英語）](docs/RECOVERY.md)の順番で戻す必要があります。
- Exitを押しながらの電源投入によるDFUは、純正ローダーとUSB経路が正常な場合の復旧手段です。
  ローダー破損、USB接続不能、工場データ紛失、ハード故障からの復旧を保証するものではありません。
- 書き込み・ゲーム中は **側面HID端子とPCだけを接続** し、測定側の両端子は空にしてください。
  DOOMアプリは通常の測定／PDアプリを置き換えます。メーカーの公式更新ではなく、保証・サポートの適用も確認していません。

**ビルド済みファームウェアは現在未公開です。** 土台となるファームウェアの再配布条件が未確定で、
リスクや自己責任の注意書きだけでは再配布の許諾を補えません。
[バイナリ公開の状況と条件（英語）](docs/BINARY-RELEASE.md)を確認してください。

## 動作状況

| 項目 | 確認結果 |
| --- | --- |
| 実機 | POWER-Z KM003C HW2.3の1台、元ファーム2.0.7 |
| 実行環境 | Cortex-M4 / HC32F460、192MHz |
| ゲーム | Freedoom 0.13.0、E1M1 |
| 表示 | 通常240×180、またはv8の正方形表示（3D 240×200＋HUD 40行） |
| 速度 | 一定間隔モードは8.75fps目標。制限なし・開始地点・プレビューOFFで通常約8.5／正方形約9.6fps |
| 操作 | 前進・旋回・射撃・扉／スイッチ・メニュー |
| PC操作 | USB経由のブラウザー操作パネル。実機で移動・旋回・射撃を確認 |
| 本体液晶 | v7でPCから明るさ調整・90°単位の左右回転に対応 |
| PCプレビュー | 通常120×90／正方形120×120・RGB565。画像保存にも対応 |
| 起動 | ボタン判定の3秒＋ゲーム読み出し照合後に自動起動。実機で起動を確認 |
| 復旧 | 純正アプリと外部NOR全4MiBの復元・読み戻し・純正起動を実機確認 |

音声、セーブ、設定保存、別マップへの遷移は今回の対応範囲外です。DOOM版では測定・PDタスクを起動しません。側面HID端子から給電し、測定側の端子には機器を接続せず使用します。

動作確認したのは**1個体のみ**です。HW2.3全個体の互換性を保証するものではありません。更新時には個別に保存したローダーとの完全一致を要求します。純正ファーム、ローダーダンプ、校正データ、シリアル番号は公開しません。生成したファームはソースツリーから除外し、将来のバイナリ添付は[公開条件](docs/BINARY-RELEASE.md)を満たしたGitHub Releasesで扱います。

## 操作方法

| 操作 | ボタン |
| --- | --- |
| 前進 | OK |
| 旋回 | 左 / 右 |
| 射撃 | Exitを短く押す |
| 扉・スイッチ | 左＋右 |
| メニューを開く | Exit＋OK |
| メニューの上下 | 左 / 右 |
| メニューの決定 / 戻る | OK / Exit |
| 自動起動を止めてUSB保守待機 | 起動時にOKを押す |
| 純正更新画面へ戻る | Exitを約2秒押す |

Exitを押したままHIDケーブルを接続しても、アプリのUSB動作に依存せず純正更新／DFU画面へ入れます。

### PCから操作する

PC操作対応版（v5）と更新したホストを用意して、次を実行します。

```powershell
.\scripts\play.ps1
```

サーバー起動後にKM003Cを接続しても、自動で認識します。抜き挿し後も自動再接続し、押下中のキーを解除するので、再度 **Enable keyboard** を押して操作を再開してください。通常のブラウザーでは、表示されたHTTP URLを開きます。`web/controller.html` の直接起動では動作しません。

開いたローカル操作パネルで **Enable keyboard** を押します。**WASD／矢印**で移動・旋回、**Space／Ctrl**で射撃、**E**で扉・スイッチ、**Esc**でメニュー、**Enter**で決定です。タブを切り替えると入力を解除し、戻った後は再びEnableを押します。ゲーム画面は本体に表示します。詳細は[PC操作ガイド（英語）](docs/PC-CONTROLS.md)を参照してください。

v7では **Meter LCD** のボタンで、本体の明るさと90°単位の左右回転を操作できます。PC表示は、ゲーム画面の位置と向きを固定し、その周りで本体画像だけを回す通常モード（初期設定）と、映像も一緒に回すネタモードを選べます。設定は電源を入れ直すと元に戻ります。

v6では同じパネルに **120×90・RGB565の実機画面プレビュー**も表示します。**Save frame** でBMP画像を保存できます。解像度、RAM使用量、更新速度の制約は[画面キャプチャの説明（英語）](docs/SCREEN-CAPTURE.md)に記載しています。

## ソースとビルド

検証環境はWindows、PowerShell、Python 3、Rust Windows GNU、LLVM-MinGWです。[SOURCE_LOCK.json](SOURCE_LOCK.json) の固定リビジョンに、管理対象のパッチと追加ソースを適用します。

**Frame pacing** で一定間隔（Steady・8.75fps目標・初期設定）と速度制限なし（Uncapped）を切り替えられます。場面ごとに変わる処理時間を揃え、入力もゲーム更新の直前に取り込むことで、古い入力が先行コマンドに残る遅れを減らしています。

v8では、左右の視野とHUDの全項目を保つ正方形版を追加しました。高速SRAMH配置、短い参照データのキャッシュ、16MHzのNOR読み出しに対応します。起動時にゲームデータ全体を従来速度と照合し、一致した場合だけ高速読み出しを使います。正方形版は `.\scripts\build-firmware.ps1 -Square` でビルドできます。[実測結果・正方形表示・LZ4／DMAの検討（英語）](docs/PERFORMANCE.md)を参照してください。

```powershell
git clone https://github.com/inuchanbt/apdo-doom-on-km003c.git
cd apdo-doom-on-km003c
python scripts/prepare-sources.py --sources-only
```

ここまではUSBにアクセスせずソースを再構成するだけです。**初回バックアップ**は `.\scripts\build-backup.ps1` で独立した読み取り専用ツールをビルドします。既存のバックアップや個体のローダーは不要です。[初回取得・検証手順（英語）](docs/FIRST-BACKUP.md)に従い、純正アプリと手動DFUの二重読み取りを検証してから、実機更新用ホストへ引き継ぎます。初回取得の対象はHW2.3・純正2.0.7です。元の1個体を純正状態へ戻して、取得・DFU照合とビルド用データへの引き継ぎを確認済みです。他個体は未検証です。環境構築、Freedoom変換、以後のビルドは[ビルド手順（英語）](docs/BUILD.md)を参照してください。

```powershell
.\scripts\build-host.ps1
.\scripts\build-firmware.ps1
```

この2つのコマンドは実機へ書き込みません。汎用インストーラーやビルド済みファームの公開はなく、[ライセンス・配布条件](docs/BINARY-RELEASE.md)の確認が必要です。

## 純正への復旧

検証した手順は、元の外部NORを復元して全4MiBを読み戻し、純正アプリを書き戻し、ローダーが不変であることと純正起動を確認します。外部NOR末尾1MiBはゲームサービスから書き込めません。

元の作業フォルダーに検証済みバックアップと設定を残した状態で実行します。

```powershell
.\scripts\restore-stock.ps1
```

詳細は[復旧手順（英語）](docs/RECOVERY.md)に記載しています。GitHubからのcloneには復旧データが含まれません。元の作業フォルダーを残し、バックアップを別の場所にも保管してください。

[検証記録（英語）](docs/VALIDATION.md)では、実機確認・ホスト描画・ビルド検査を分けて記載しています。実機でのゲーム操作と、外部データを含む純正復元まで確認済みです。
