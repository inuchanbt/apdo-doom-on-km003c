# Experimental prebuilt installation — HW2.3 only

Release: [v0.1.0-independent](https://github.com/inuchanbt/apdo-doom-on-km003c/releases/tag/v0.1.0-independent).

**This can permanently disable the meter or lose factory data. Recovery is not
guaranteed; repair/replacement may be necessary.** Only one HW2.3 unit originally
running stock 2.0.7 was tested. On 2026-10-31 the owner confirmed the complete
independent first-install/NOR-write/stock-restore workflow on that same unit;
other units and failure-recovery scenarios remain unqualified. This is an unofficial
Pre-release for experimenters, without project warranty; manufacturer approval/support is not claimed.

DOOM replaces the stock tester app. There is no measurement, PD negotiation or
stock tester UI while installed. Keep both measurement connectors EMPTY and use
only the SIDE HID connector. Never flash a loader/ICG or another unit's backups.
Stop on a hardware, port, hash or readback mismatch; do not force or blindly retry.
Loading this file in the manufacturer's graphical updater is **untested**.

## 1. Obtain the release and build the host tools

Download the recommended `-firmware.zip` (update container + notices + guide),
`-freedoom-e1m1.zip`, `-source.tar.gz`, `-notices.zip` and
`SHA256SUMS.txt` from the same tagged Release. Verify the downloaded files with
SHA-256 (`Get-FileHash FILE -Algorithm SHA256`) against that checksum file.
The source ZIP automatically generated by GitHub is **not** the complete source
bundle. Use the explicitly attached source tarball.

Unpack the source tarball. Follow `docs/RELEASE-BUILD.md` to install the recorded
Rust/LLVM/Python toolchains and build the host and read-only backup utility:

```powershell
. .\scripts\env.ps1
.\scripts\build-host.ps1
.\scripts\build-backup.ps1
New-Item -ItemType Directory -Force backups,artifacts | Out-Null
```

No device backup is needed to build these tools. They embed no private loader or
serial. No host executable is supplied in this release.

Set paths to your actual downloaded/unpacked files, from the project directory:

```powershell
$taskHost = '.\independent\target\release\apdo-host.exe'
$taskBackup = '.\bootstrap\target\release\km003c-backup.exe'
$taskFirmware = 'C:\path\to\apdo-doom-km003c-hw2.3-v0.1.0-independent.mencrypt'
$taskPack = 'C:\path\to\unpacked-freedoom-e1m1\DOOM.DAT'
$taskStock = 'backups\stock-original'
$taskNor = 'backups\nor-original'
```

The application contains the startup logo, **not** playable game data. The separate
pack must be exactly 2,802,000 bytes with SHA-256
`6b25a4f1adb6f1f1f5f42226c272b93ccff4f356ac8d7034cf83712b2da70c08`.
It is Freedoom E1M1, not a commercial DOOM IWAD.

## 2. Acquire and qualify this meter's original data BEFORE flashing

Start with the untouched stock app and the same physical PC USB port throughout.
Use only one attached meter. Replace `YOUR_SERIAL` with this meter's own serial:

```powershell
& $taskBackup inspect
& $taskBackup stock --serial YOUR_SERIAL --output $taskStock
```

This reads the stock app, loader, internal tail, calibration and first 3 MiB of
external NOR twice and validates their records/CRC. It is **not yet a complete
4 MiB NOR backup**. Do not write game data.

Unplug HID; hold Exit while reconnecting the same cable/PC port. Release Exit on
the native update/DFU screen. Then run the read-only qualification:

```powershell
& $taskBackup dfu-check --stock $taskStock
& $taskBackup verify --stock $taskStock --require-dfu
& $taskHost package-installed "$taskStock\stock-app.bin" "$taskStock\restore.mencrypt"
```

Before continuing, preserve another offline copy of the entire qualified backup
and original restore package. Read [FIRST-BACKUP.md](FIRST-BACKUP.md) for what is
checked. No original stock/loader/calibration images are provided by the project.

## 3. Flash only the app, then acquire the full original NOR BEFORE game writes

Remain in qualified native DFU. Use a new evidence/output directory each time:

```powershell
& $taskHost flash $taskStock $taskFirmware artifacts\first-app-flash
& $taskHost start $taskStock $taskFirmware
& $taskHost nor-backup $taskStock $taskNor
```

Flash validates this meter's loader against its qualified backup before writing,
then reads every application byte back and confirms unchanged loader bytes.
The original external NOR has not yet been overwritten. The new service shows
its Freedoom banner. The backup command pauses automatic startup, reads all
4 MiB twice, and requires its first 3 MiB to match the qualified stock acquisition.
**Do not install the game until full original NOR acquisition succeeds.**

## 4. Install the separate game data

```powershell
& $taskHost install-game $taskStock $taskNor $taskPack artifacts\game-preflight --dry-run
& $taskHost install-game $taskStock $taskNor $taskPack artifacts\game-install
& $taskHost play
python scripts/pc-controller.py --port 50594
```

The installer checks the exact pack hash, complete original backup, recorded USB
port, protected final 1 MiB and complete current prefix **before erase**. Only
changed sectors below 3 MiB are programmed; bytes outside the pack retain their
original values. It verifies all 4 MiB afterwards. There are no force/bypass
options. An ambiguous write failure is not retried. Preserve failure evidence;
do not continue to game/stock startup after a failed readback.

Open the printed HTTP URL (not the HTML file). Enable keyboard to play. Normal
power-on shows the Freedoom banner for the existing three-second boot window,
keeps it visible during data verification, then starts DOOM. Hold OK during
startup to cancel automatic boot for storage service. Hold Exit for two seconds
to request native DFU. Live preview may reduce game smoothness; turn it off for
play. No charging/tester use is supported while this app is installed.

## 5. Return to stock: restore NOR FIRST, then the original app

Stop the Web controller. Run `& $taskHost loader` to enter native DFU. Hold the
physical OK button while starting the independent app again:

```powershell
& $taskHost start $taskStock $taskFirmware
```

Release OK after startup. `& $taskHost info` must show no rendered frames;
pausing an already initialized engine does not enable NOR writes. Then:

```powershell
& $taskHost restore-nor $taskStock $taskNor $taskPack artifacts\nor-restore
& $taskHost loader
& $taskHost flash $taskStock "$taskStock\restore.mencrypt" artifacts\stock-app-restore
& $taskHost start $taskStock "$taskStock\restore.mencrypt"
```

Continue to the stock app only after complete original NOR readback succeeds.
A stock application file alone is **not** a complete rollback. The protected tail
must match and is never rewritten by the game service. Stock app readback and
identity are checked, but neither those checks nor a backup guarantee recovery.
Confirm the original UI and functions physically. The owner confirmed the new
full install/restore workflow on 2026-10-31; this remains an experimental procedure
verified on one unit. See [VALIDATION.md](VALIDATION.md) for the scope of that report.

For a failed startup in native DFU, preserve read-only diagnostics with
`& $taskHost diagnostics $taskStock NEW_OUTPUT_DIRECTORY`. Do not substitute
another unit's recovery material. See [BINARY-RELEASE.md](BINARY-RELEASE.md) for
precise tested/untested scope and licensing/source details.
